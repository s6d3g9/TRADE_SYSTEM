# Хранение пользовательской информации

Источник истины по структуре хранения и отчётности: [README_DATA_STORAGE_STRATEGIES.md](README_DATA_STORAGE_STRATEGIES.md).

## Где и как хранятся данные

- **Postgres** (через backend):
  - Все основные сущности: стратегии, модели, сонастройки, версии конфигов, боты
  - Каждая запись содержит created_at, updated_at
  - Конфиги (ConfigFile) могут быть активными/неактивными
- **Redis**:
  - Очереди задач (например, autotune)
  - Pub/sub для событий
- **Файлы**:
  - финальный bot config.json и другие тяжёлые артефакты (например результаты бэктестов) — сохраняются на диск, с метаданными/ссылками из БД
  - исходники стратегий — в git; backend может клонировать/кэшировать репозиторий на диск по запросу

## Примеры

- Пользователь создаёт стратегию — запись в таблице `strategy_templates` (модель StrategyTemplate)
- Запускает autotune — создаётся новая версия `config_files` (scope=alignment|model|strategy)
- Генерирует бота — config.json пишется на диск, создаётся запись в bots
