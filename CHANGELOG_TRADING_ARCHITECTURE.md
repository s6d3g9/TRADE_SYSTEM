# Обновление архитектуры хранения данных для торговых ботов

**Дата:** 22 декабря 2025  
**Статус:** ✅ Разработано, готово к тестированию

## Проблема

Старая структура таблицы `bots` была слишком упрощенной:
- Не хранила информацию о времени работы бота
- Не отслеживала сессии запуска
- Не сохраняла торговые сделки и позиции
- Не поддерживала разные режимы работы (backtest, dry_run, live)
- Не собирала метрики производительности

## Решение

Разработана комплексная архитектура для хранения данных о:
1. **Ботах** - конфигурация и состояние
2. **Сессиях** - каждый запуск бота
3. **Сделках** - все торговые операции
4. **Позициях** - открытые позиции
5. **Бектестах** - результаты тестирования
6. **Метриках** - периодические снимки состояния
7. **Биржевых аккаунтах** - API ключи

## Что было создано

### 1. Модели данных
📁 `backend/app/models/trading.py`
- `Bot` - основная таблица ботов с расширенными полями
- `BotSession` - сессии работы бота
- `Trade` - торговые сделки
- `Position` - открытые позиции
- `Backtest` - результаты бектестов
- `BotMetric` - метрики в реальном времени
- `ExchangeAccount` - учетные записи бирж

### 2. Миграция базы данных
📁 `backend/alembic/versions/20251222_01_create_trading_tables.py`
- Создает все новые таблицы
- Удаляет старую упрощенную таблицу `bots`
- Добавляет индексы для производительности
- Поддерживает откат (downgrade)

### 3. Pydantic схемы
📁 `backend/app/schemas/trading.py`
- Схемы для создания/обновления всех сущностей
- Схемы для ответов API
- Схемы для агрегированной статистики

### 4. API endpoints
📁 `backend/app/api/trading.py`
- CRUD операции для ботов
- Управление сессиями
- Работа со сделками и позициями
- Получение метрик и статистики
- 30+ эндпоинтов

### 5. Документация
- 📁 `README_BOT_ARCHITECTURE.md` - полная архитектура БД
- 📁 `README_TRADING_USAGE.md` - руководство по использованию

## Ключевые возможности

### Режимы работы
- ✅ **Backtest** - тестирование на исторических данных
- ✅ **Dry Run** - виртуальная торговля (paper trading)
- ✅ **Live** - реальная торговля с реальными деньгами

### Отслеживание состояния
- ✅ Uptime бота (время работы каждой сессии)
- ✅ Статус (created → running → stopped/paused/error)
- ✅ Начальный и текущий баланс
- ✅ Количество открытых позиций
- ✅ Реализованный и нереализованный PnL

### Торговая активность
- ✅ Все сделки с полными деталями
- ✅ Открытые позиции с текущими ценами
- ✅ Stop-loss и Take-profit
- ✅ Комиссии биржи
- ✅ Связь позиций со сделками

### Метрики и аналитика
- ✅ Периодические снимки состояния
- ✅ Баланс во времени
- ✅ PnL динамика
- ✅ Win rate статистика
- ✅ Агрегированная статистика по ботам

### Бектестинг
- ✅ Параметры теста (период, пара, таймфрейм)
- ✅ Метрики доходности
- ✅ Риск-метрики (Sharpe, Sortino, max drawdown)
- ✅ Детальная статистика сделок

## Структура данных

```
users (1) ----< (N) bots
                     │
                     ├──< (N) bot_sessions
                     │         │
                     │         ├──< (N) trades
                     │         ├──< (N) positions
                     │         └──< (N) bot_metrics
                     │
                     └──< (N) backtests

strategy_alignments (1) ----< (N) bots
                            └──< (N) backtests
```

## API Examples

### Создать бота
```http
POST /api/trading/bots
{
  "name": "My BTC Bot",
  "config_path": "/configs/bot.json",
  "exchange": "binance",
  "mode": "dry_run"
}
```

### Получить список ботов
```http
GET /api/trading/bots
```

### Запустить бота (создать сессию)
```http
POST /api/trading/sessions
{
  "bot_id": "bot-123",
  "initial_balance": 1000.0
}
```

### Получить открытые позиции
```http
GET /api/trading/bots/bot-123/positions?status=open
```

### Получить метрики
```http
GET /api/trading/bots/bot-123/metrics?limit=100
```

### Закрыть позицию
```http
POST /api/trading/positions/pos-456/close
```

## Преимущества новой архитектуры

1. **Полная история** - каждый запуск бота записывается
2. **Детальная аналитика** - все метрики для построения графиков
3. **Режимы работы** - backtest, dry_run, live в одной системе
4. **Масштабируемость** - оптимизированные индексы для больших объемов
5. **Безопасность** - шифрование API ключей бирж
6. **Гибкость** - легко добавлять новые поля через JSONB

## Риски и ограничения

1. **Объем данных** - таблицы trades и bot_metrics будут расти быстро
   - Решение: периодическая архивация старых данных
   
2. **Производительность** - много JOIN'ов для получения полной картины
   - Решение: денормализация критичных данных, кэширование

3. **Миграция** - потеря старых данных при переходе
   - Решение: экспорт старых данных перед миграцией
