# UI Design Principles

## Архитектурные правила для построения интерфейса Trade System

### 1. Сворачиваемость секций (Collapsible Sections)

**Правило:** Все секции интерфейса ДОЛЖНЫ быть сворачиваемыми.

#### Обоснование:
- Улучшает навигацию на страницах с большим количеством контента
- Позволяет пользователям фокусироваться на важных разделах
- Экономит пространство на экране
- Повышает производительность при рендеринге больших объемов данных

#### Статус внедрения:

✅ **Применено на страницах:**
- `/profile` - ProfilePage (Trading Overview, Performance Metrics, Best Bot)
- `/dashboard/overview` - OverviewPage (Backend Health, StrategyLab Catalog)
- `/strategylab/combinator` - CombinatorPageV2 (Bot Generator с columns)

⏳ **Ожидает внедрения:**
- Остальные страницы Dashboard (LivePage, AlertsPage)
- StrategyLab страницы (BacktestDetailPage, OptimizePage и др.)
- Settings страницы
- Agents страницы

#### Реализация:

Используйте компонент `CollapsibleSection` из `frontend/src/shared/ui/CollapsibleSection.tsx`:

```tsx
import CollapsibleSection from '@/shared/ui/CollapsibleSection'

<CollapsibleSection
  title="Название секции"
  icon="🔧"
  defaultExpanded={true}
  variant="card"
  headerActions={
    <button>Действие</button>
  }
>
  {/* Содержимое секции */}
</CollapsibleSection>
```

#### Варианты отображения (variants):

1. **default** - стандартная секция с фоном и границей
2. **card** - секция в виде карточки с закругленными углами
3. **minimal** - минималистичная секция только с нижней границей

#### Управление несколькими секциями:

Используйте хук `useCollapsibleSections` для управления состоянием нескольких секций:

```tsx
const { sections, toggle, expandAll, collapseAll, isExpanded } = useCollapsibleSections({
  filters: true,
  results: true,
  settings: false,
})

// Управление всеми секциями
<button onClick={expandAll}>Развернуть все</button>
<button onClick={collapseAll}>Свернуть все</button>

// Отдельные секции
<CollapsibleSection
  title="Фильтры"
  defaultExpanded={isExpanded('filters')}
  onToggle={() => toggle('filters')}
>
  {/* ... */}
</CollapsibleSection>
```

#### Сохранение состояния:

Для сохранения состояния секций между сессиями используйте localStorage:

```tsx
const [expanded, setExpanded] = useState(() => {
  const saved = localStorage.getItem('section_my_section')
  return saved ? JSON.parse(saved) : true
})

const handleToggle = (isExpanded: boolean) => {
  setExpanded(isExpanded)
  localStorage.setItem('section_my_section', JSON.stringify(isExpanded))
}

<CollapsibleSection
  title="Моя секция"
  defaultExpanded={expanded}
  onToggle={handleToggle}
>
  {/* ... */}
</CollapsibleSection>
```

#### Примеры применения:

✅ **Правильно:**
- Формы с множеством полей разбиты на логические секции
- Таблицы с фильтрами в сворачиваемых панелях
- Дашборды с независимыми виджетами
- Настройки, сгруппированные по категориям
- Списки элементов с детальной информацией

❌ **Неправильно:**
- Секция содержит только одно поле или элемент
- Критичная информация скрыта по умолчанию без индикации
- Секции слишком мелкие (менее 3-4 элементов)

#### Доступность (Accessibility):

- ✅ Секции управляются с клавиатуры (Enter/Space)
- ✅ Четкая визуальная индикация состояния (развернуто/свернуто)
- ✅ Плавная анимация перехода
- ✅ Состояние фокуса для навигации

### 2. Модульное отображение элементов (Module Badges)

**Правило:** Названия стратегий, моделей, конфигураций и подобных сущностей ДОЛЖНЫ отображаться как модули с рамкой.

#### Обоснование:
- Визуально выделяет важные элементы (стратегии, модели, конфиги)
- Создает четкую иерархию и группировку информации
- Улучшает читаемость и сканируемость интерфейса
- Обеспечивает единый стиль отображения модульных компонентов

#### Визуальный стиль:

- **Рамка:** 1.5px solid с цветом категории
- **Фон:** Полупрозрачный цвет категории (08 alpha)
- **Тень:** Дополнительная обводка (15 alpha) для глубины
- **Радиус:** 6px для мягких углов
- **Padding:** 4px 8px для компактности
- **Иконка:** Эмодзи слева от текста

#### Цветовая схема:

```tsx
Стратегии:  #22c55e (зеленый) 📊
Модели:     #8b5cf6 (фиолетовый) 🧠
Alignments: #3b82f6 (синий) 🔗
Конфиги:    #f59e0b (оранжевый) ⚙️
Боты:       #06b6d4 (cyan) 🤖
```

#### Правила применения:

1. **Автогенерируемые идентификаторы** - используйте короткий ID вместо полного имени:
   ```tsx
   // ✅ Правильно - Bot ID как код
   <ModuleBadge icon="🤖" color={MODULE_COLORS.bot}>
     {bot.bot_id.slice(0, 12)}
   </ModuleBadge>
   
   // ❌ Неправильно - дублирование информации
   <div>Bot: Strategy Name + Model Name</div>
   ```

2. **Избегайте дублирования** - если название бота = стратегия + модель, показывайте только стратегию и модель отдельно

3. **Используйте иконки для типизации** - каждый тип модуля имеет свою иконку

4. **ОБЯЗАТЕЛЬНО: Адаптивный размер текста** - текст должен автоматически подстраиваться под ширину контейнера:
   ```tsx
   // ✅ ПРАВИЛЬНАЯ структура ModuleBadge
   <div style={{
     display: 'inline-flex',
     maxWidth: '100%',        // Адаптация к контейнеру
     minWidth: 0,             // Позволяет сжатие
   }}>
     <span style={{ flexShrink: 0 }}>📊</span>  // Иконка не сжимается
     <span style={{
       whiteSpace: 'nowrap',       // Текст в одну строку
       overflow: 'hidden',         // Скрыть переполнение
       textOverflow: 'ellipsis',   // Добавить "..."
       minWidth: 0,                // Позволить обрезку
     }}>
       {text}
     </span>
   </div>
   
   // ❌ НЕПРАВИЛЬНО - текст выходит за границы
   <div style={{ display: 'inline-flex' }}>
     {icon}{text}
   </div>
   ```

5. **Длинные названия** - всегда обрезаются с многоточием: "NostalgiaForInfinityX3" → "NostalgiaForIn..."

6. **ОБЯЗАТЕЛЬНО: Полный текст при наведении** - если текст обрезан, при наведении ДОЛЖЕН отображаться полный текст (tooltip через `title`).

#### Реализация:

Используйте компонент `ModuleBadge` из `frontend/src/shared/ui/ModuleBadge.tsx`:

```tsx
import ModuleBadge from '@/shared/ui/ModuleBadge'
import { MODULE_COLORS } from '@/shared/styles/designSystem'

// Использование (обрезка + tooltip полного значения)
<ModuleBadge icon="📊" color={MODULE_COLORS.strategy} text="NostalgiaForInfinityX7" />

// Для автокодов можно показывать короткое значение, но tooltip — полный
<ModuleBadge
  icon="🤖"
  color={MODULE_COLORS.bot}
  text={bot.bot_id.slice(0, 12)}
  title={bot.bot_id}
/>
```

#### Примеры применения:

✅ **Правильно:**
- Названия стратегий в списках ботов
- Модели в конфигураторе
- Alignments в grid-панели
- Названия конфигов в карточках
- Теги и метки категорий
- Bot ID как код (автогенерируемые идентификаторы)

❌ **Неправильно:**
- Обычный текст без модульности
- Кнопки действий (используйте стандартные кнопки)
- Длинные описания или параграфы
- Статусы (используйте status badges)
- Дублирование информации (например, "Bot: Strategy + Model" вместо раздельного отображения)

#### Статус внедрения:

✅ **Применено:**
- CombinatorPageV2: отображение стратегий и моделей в списке ботов

⏳ **Ожидает внедрения:**
- Все страницы со списками стратегий/моделей/конфигов
- Карточки в каталогах
- Детальные страницы элементов

### 3. Прокрутка и компоновка страниц (Scrollable Layout)

**Правило (для всех страниц):** По умолчанию страница ДОЛЖНА иметь **один общий скролл документа**.

Внутренние скроллы (`overflowY: auto`) допускаются только **внутри конкретной секции** и только для длинных списков/таблиц/логов, когда это действительно необходимо.

#### Обоснование:
- Предотвращает ситуации, когда контент уходит за пределы экрана
- Обеспечивает доступность всех элементов интерфейса
- Гарантирует правильное поведение прокрутки на разных разрешениях экрана
- Позволяет добавлять новые секции без “двух окон” прокрутки

#### Проблема:
```tsx
// ❌ НЕПРАВИЛЬНО
// 1) Фиксированная высота страницы + 2) внутренние скроллы на больших блоках
// -> создаются “несколько окон” прокрутки, часть контента сложно/невозможно увидеть
<div style={{ height: 'calc(100vh - 60px)', overflowY: 'hidden' }}>
  <div style={{ overflowY: 'auto', maxHeight: '60vh' }}>Секция 1</div>
  <div style={{ overflowY: 'auto' }}>Секция 2</div>
</div>
```

#### Решение:

**Базовый шаблон: один общий скролл страницы**

```tsx
// ✅ ПРАВИЛЬНО — секции идут по потоку, раскрытие увеличивает высоту страницы
<div style={{
  minHeight: '100vh',
  background: 'var(--bg)',
  display: 'flex',
  flexDirection: 'column',
}}>
  <div style={{ padding: SPACING.xxl, display: 'flex', flexDirection: 'column', gap: SPACING.xxl }}>
    <CollapsibleSection title="Секция 1" variant="card">
      {/* Контент */}
    </CollapsibleSection>

    <CollapsibleSection title="Секция 2" variant="card">
      {/* Контент */}
    </CollapsibleSection>
  </div>
</div>
```

**Исключение: внутренний скролл только для длинного списка внутри секции**

```tsx
// ✅ ДОПУСТИМО — внутренний скролл ограничен конкретным списком/таблицей
<CollapsibleSection title="Trades" variant="card">
  <div style={{ maxHeight: '50vh', overflowY: 'auto' }}>
    {/* Длинная таблица/список */}
  </div>
</CollapsibleSection>
```

#### Правила компоновки:

1. **Страница:**
  - НЕ фиксируйте высоту страницы под viewport (`height: '100vh'` / `calc(100vh - ...)`) как основной паттерн.
  - Используйте естественный поток и общий скролл документа.

2. **Контент:**
  - Секции идут одна под другой и увеличивают высоту страницы при раскрытии.
  - Избегайте `overflowY: 'auto'` на крупных layout-контейнерах страницы.

3. **Внутренние скроллы:**
  - Разрешены точечно: только для конкретных таблиц/списков/логов внутри секции.
  - Всегда ограничивайте `maxHeight`, чтобы не ломать общий UX.

#### Примеры применения:

✅ **Правильно:**
- Bot Generator + Active Bots — как две обычные секции на странице
- Filters + Results Table — страница скроллится целиком
- Settings Tabs + Settings Content — страница скроллится целиком
- Длинные таблицы/логи имеют локальный скролл внутри секции

❌ **Неправильно:**
- Страница с несколькими “окнами” скролла (несколько больших контейнеров с `overflowY: 'auto'`)
- Фиксировать высоту страницы так, что нижние секции недоступны
- Делать внутренний скролл на уровне всей страницы вместо локального списка/таблицы

#### Статус внедрения:

✅ **Применено:**
- CombinatorPageV2: один общий скролл страницы, секции в потоке

### 4. Подсекция настроек для каждого бота (Bot Config Menu)

**Правило (для всех страниц со списком ботов):** Внутри информационной подсекции каждого бота ДОЛЖНО быть **сворачиваемое меню** для сонастройки/конфигурирования.

Меню ДОЛЖНО содержать:
- Выбор биржи
- Поле ввода токена биржи
- Выбор AI-провайдера (включая OpenRouter)
- Поле ввода токена AI-провайдера
- Если выбран OpenRouter — выбор модели из OpenRouter

Доп. правило:
- В списке моделей OpenRouter бесплатные модели ДОЛЖНЫ быть явно помечены тегом/лейблом `FREE`.

### 5. Редактирование конфигов стратегии внутри бота (Split Config Editor)

**Правило (для всех страниц со списком ботов):** В информационной подсекции каждого бота ДОЛЖНЫ быть:

1) Подсекция выбора `Strategy / Model / Alignment` (сворачиваемая)

2) Подсекция `Config editor` (сворачиваемая), которая открывает split-view:
- Слева — текстовый редактор с **оригинальным** содержимым конфиг-файла
- Справа — окно чат-бота/чат-редактора
  - в поле ввода автоматически подставляется текущее содержимое конфига
  - чат используется для инструкции по настройке стратегии/конфига

**Реализация:** все подсекции делаются через `CollapsibleSection` (variant `card`).

#### Реализация:

Используйте `CollapsibleSection` (вариант `card`) внутри раскрываемой части бота:

```tsx
{expanded && (
  <div>
    <CollapsibleSection
      title="Config tuning menu"
      icon="⚙️"
      defaultExpanded={false}
      variant="card"
    >
      {/* Exchange select + exchange token input */}
      {/* AI agent select + AI agent token input */}
    </CollapsibleSection>
  </div>
)}
```

#### Примечания:
- Это меню — часть информационной подсекции бота (не отдельная страница/модалка).
- Меню ДОЛЖНО быть сворачиваемым по стандарту секций.

⏳ **Ожидает внедрения:**
- Остальные страницы с множественными секциями
